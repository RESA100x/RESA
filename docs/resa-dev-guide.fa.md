# راهنمای توسعهٔ RESA

این سند برای کسی است که بعداً می‌خواهد روی همین مخزن کار را ادامه بدهد: معماری
کجاست، داده از کجا می‌آید، هر ماژول کدام فایل‌ها را دارد و چه قواعدی را نباید
شکست. برای ساخت و انتشار نسخه، [راهنمای ساخت و انتشار](resa-build-release.fa.md)
را بخوانید؛ برای وضعیت فعلی و کارهای باقی‌مانده،
[وضعیت و نقشهٔ راه](resa-status-roadmap.fa.md).

## ۱) نمای کلی

RESA یک برنامهٔ دسکتاپ Tauri 2 است: رابط کاربری React + TypeScript، هستهٔ Rust،
و SQLite به‌عنوان منبع حقیقت. هیچ سروری برای کار عادی لازم نیست؛ سینک آنلاین
اختیاری است.

```text
React (src/)
  └── RepositoryContext  ← یک شیء NowlyRepository در اختیار کل درخت می‌گذارد
        └── tauri-nowly-repository.ts   (پیاده‌سازی واقعی: invoke)
              └── src-tauri/src/*.rs   (دستورهای Tauri)
                    └── db.rs          (SQLite + مایگریشن‌ها)
```

- `src/data/nowly-repository.ts` فقط **قرارداد** است (تایپ‌ها و امضاها). هیچ
  ماژولی مستقیماً `invoke` صدا نمی‌زند؛ همه از مسیر repository رد می‌شوند تا
  تست‌ها و حالت مرورگر بدون Tauri هم کار کنند.
- `src/data/tauri-nowly-repository.ts` پیاده‌سازی واقعی است و نام دستورهای
  Rust را نگه می‌دارد. اگر نام دستور یا شکل دادهٔ برگشتی را عوض کردید، هر دو
  طرف باید هم‌زمان تغییر کنند.
- `src/data/browser-tauri-shim.ts` برای اجرای رابط در مرورگر (توسعه/تست) است.

## ۳) داده و دیتابیس

- فایل دیتابیس: `resa.sqlite` در پوشهٔ دادهٔ برنامه
  (`%APPDATA%\com.resa.app` در ویندوز). دیتابیس قدیمی `nowly.sqlite` و پوشهٔ
  `com.nowly.app` یک‌بار و خودکار منتقل می‌شوند (`adopt_legacy_*` در `db.rs`).
- مایگریشن‌ها در `src-tauri/src/db.rs` با شمارهٔ صعودی و جدول
  `schema_migrations` هستند (اکنون بیش از ۵۰ مورد). **قاعده:** هیچ‌وقت مایگریشن
  قبلی را ویرایش نکنید؛ فقط شمارهٔ تازه اضافه کنید.
- قبل از هر مایگریشن یک snapshot با نام `RESA-<تاریخ>.sqlite` در همان پوشه
  ساخته می‌شود؛ اگر کاربر گفت «داده‌ام پاک شد»، اول همان‌جا را بگردید.
- بکاپ دستی/خروجی کامل از «تنظیمات ← پشتیبان‌گیری» انجام می‌شود
  (`src-tauri/src/backup.rs`).
- عکس‌ها و فایل‌ها به‌صورت فایل جدا در پوشهٔ داده ذخیره می‌شوند، نه BLOB.
  استثنا: گاوصندوق مدارک که رمزنگاری‌شده است (PBKDF2-HMAC-SHA256 +
  AES-256-GCM در `vault.rs`؛ PIN ذخیره نمی‌شود).

## ۴) ماژول‌ها و چیدمان

- فهرست ماژول‌ها در `src/widgets/widget-registry.ts` است: `builtinDefinitions`
  (تقویم، ماتریس، یادداشت) و ماژول‌های اختیاری (کانبان، زمان، جلسات، بایگانی،
  پروژه‌ها، گزارش‌ها، دفتر تلفن، گیاهان، کتابخانه، برچسب).
- شبکه ۱۲ ستون × ۸ سطر است (`GRID_COLS` / `GRID_ROWS`) و هر ماژول `minW/minH`
  و مستطیل پیش‌فرض دارد.
- چیدمان در دیتابیس ذخیره می‌شود؛ قالب‌ها (templates) هم همان‌جا هستند.
- روی موبایل `MobileShell` جای `DesktopShell` را می‌گیرد: ماژول‌ها به صفحه
  تبدیل می‌شوند و میان‌برهای پایین صفحه در `src/app/layout/mobile-shortcuts.ts`
  تعریف شده‌اند (ذخیره در `localStorage` با کلید `resa.mobile.shortcuts`).

### الگوی «بلاک یک‌در‌یک + پنجره»

ماژول‌های سنگین (دفتر تلفن، جلسات، کتابخانه، گیاهان) یک بلاک کوچک مربعی
هستند که با کلیک، پنجرهٔ کامل خودشان را باز می‌کنند. اگر ماژول تازه‌ای اضافه
می‌کنید که فهرست/فرم زیاد دارد، همین الگو را تکرار کنید تا شبکه شلوغ نشود.
جزئیات در [دفتر تلفن](resa-phonebook.fa.md) (بخش «الگو: بلاک یک‌در‌یک»).

## ۵) فارسی، RTL و تقویم شمسی

- همهٔ متن‌ها از `t('key')` می‌آیند (`src/i18n/index.ts`)؛ متن فارسی داخل
  کامپوننت ننویسید. کلیدها در `src/i18n/translations.ts` و
  `src/i18n/supplemental.ts` هستند.
- زبان پیش‌فرض فارسی است و چیدمان RTL؛ CSS باید با `dir="rtl"` درست بماند
  (از logical properties مثل `margin-inline-start` استفاده کنید، نه `left/right`).
- تاریخ‌ها از مسیر تقویم شمسی رد می‌شوند (`src/calendar/jalali-view.ts`) و
  انتخابگر تاریخ برنامه خودش است؛ کتابخانهٔ تاریخ مرورگر را مستقیم صدا نزنید.
- خطاهای Rust که به کاربر می‌رسند باید از `localize-error.ts` بگذرند تا پیام
  فارسی شود.

## ۶) تست و بررسی

```powershell
npm ci
npm test                      # Vitest؛ حدود ۲۰۳۰ تست
npx tsc --noEmit              # typecheck
npm run version:check         # هم‌خوانی نسخه در ۵ فایل
cargo test --manifest-path src-tauri/Cargo.toml
npm run e2e -- <spec>         # Playwright
```

CI (`.github/workflows/ci.yml`) روی هر push به `main`/`mobile` و روی هر PR همین
سه مورد را اجرا می‌کند: `version:check`، `tsc`، `npm test`. نام job آن `test`
است و روی `main` به‌عنوان status check اجباری تنظیم شده.

## ۷) قواعد کار در این مخزن

- قبل از هر تغییر ظاهری، `design.md` را کامل بخوانید؛ مرجع نهایی طراحی است.
- پیام کامیت: `<type>: <توضیح>` (نمونه: `fix: ...`). تاریخچه انگلیسی است؛ همین
  سبک را نگه دارید.
- تست‌ها همراه تغییر نوشته شوند؛ تست‌های flaky را با انتظار روی وضعیت واقعی
  (مثلاً `toBeEnabled`) درست کنید، نه با `sleep`.
- فایل‌های تولیدشدهٔ اندروید و `tauri.properties` را دستی ویرایش نکنید؛
  `scripts/android-gen-gradle.mjs` آن‌ها را می‌سازد.
- نسخه همیشه باید جلو برود؛ هرگز آن را پایین نیاورید.

## ۸) افزودن یک ماژول تازه (چک‌لیست)

1. مدل و تایپ‌ها را در `src/<module>/<module>-model.ts` بسازید.
2. متدهای repository را در `src/data/nowly-repository.ts` اضافه کنید و در
   `tauri-nowly-repository.ts` پیاده کنید.
3. سمت Rust: فایل `<module>.rs`، جدول‌ها با مایگریشن تازه، دستورها را در
   `lib.rs` ثبت کنید.
4. اگر ماژول باید سینک شود، تریگرهای `sync_outbox` را در همان مایگریشن
   اضافه کنید (الگوی جدول‌های موجود را ببینید).
5. تعریف ماژول در `widget-registry.ts` + کامپوننت در `src/<module>/`.
6. کلیدهای ترجمه در `translations.ts` (فارسی و بقیهٔ زبان‌ها).
7. تست: کامپوننت، hook و در صورت لزوم تست Rust.

## ۹) عیب‌یابی سریع

| نشانه | علت رایج |
| --- | --- |
