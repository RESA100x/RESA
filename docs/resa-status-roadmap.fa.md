# وضعیت پروژه و نقشهٔ راه

این سند «عکس لحظه‌ای» است: چه چیزی ساخته و منتشر شده، چه چیزی در کد آماده
است ولی فعال نیست، چه کاری باقی مانده و چه تصمیم‌هایی گرفته شده که بعداً نباید
نقض شوند. آخرین به‌روزرسانی: نسخهٔ `0.2.31`.

## ۱) آماده و منتشرشده

- **دسکتاپ ویندوز:** نصب‌کنندهٔ NSIS و MSI با به‌روزرسانی درون‌برنامه‌ای
  (بررسی نسخه از GitHub Releases).
- **اندروید:** APK امضاشدهٔ arm64 که از همان Release دانلود می‌شود؛ رابط
  موبایل جدا (`MobileShell`) با میان‌برهای قابل جابه‌جایی در پایین صفحه،
  اعلان/یادآور با `AlarmManager` (حتی وقتی برنامه بسته است)، خروجی فایل به
  پوشهٔ Downloads.
- **ماژول‌ها:** تقویم شمسی با تکرار و استثنا، ماتریس آیزنهاور، کانبان،
  وظایف کاری، پروژه‌ها، یادداشت، برچسب، زمان/آلارم/تمرکز، جلسات، دفتر تلفن،
  کتابخانه، گیاهان (انیمیشن اختصاصی هر گونه)، گزارش کارها، بایگانی، اسکرین‌شات
  و تاریخچهٔ آن، RESA Bar.
- **زیرساخت:** تقویم شمسی، RTL کامل، چندزبانه (فارسی پیش‌فرض)، پشتیبان‌گیری
  یک‌کلیکی، پالت فرمان و جست‌وجوی سراسری، قالب‌های چیدمان، نمایش روی چند
  مانیتور (اختیاری).
- **حساب و گاوصندوق:** پروفایل، مدارک رمزنگاری‌شده با PIN، خروجی ZIP،
  ورود/ثبت‌نام اختیاری.

## ۲) در کد آماده است، ولی به سرویس نیاز دارد

**سینک آنلاین (BaaS)** — سمت کلاینت کامل است: جدول‌های سینک‌شونده،
`sync_outbox` با تریگر، push/pull با حل اختلاف «آخرین نویسنده برنده»، سینک
خودکار هر ۲ دقیقه، ثبت‌نام/ورود با ایمیل. سمت سرور فقط یک فایل SQL دارد:
`src-tauri/migrations/baas/0001_sync.sql` (جدول `sync_records`، RLS و تابع
`sync_push`). مراحل راه‌اندازی در [راهنمای سینک](sync-setup.fa.md).

**اتصال تقویم‌های بیرونی** — Google/Microsoft (OAuth) و ICS و Axelor در کد
هستند؛ برای OAuth باید `src-tauri/oauth-credentials.json` ساخته شود (در git
نیست). جزئیات در [اشتراک تقویم](calendar-sharing.fa.md) و
[Axelor](axelor-sync.fa.md).

## ۳) کارهای باقی‌مانده (به ترتیب پیشنهادی)

1. **راه‌اندازی سرور سینک:** ساخت پروژهٔ BaaS، اجرای `0001_sync.sql`، روشن
   کردن تأیید ایمیل و SMTP، سپس وارد کردن Endpoint و anon key در برنامه.
2. **تأیید پیامکی:** Supabase Auth برای ایران درگاه پیامک ندارد؛ باید یک Edge
   Function با درگاه داخلی (کاوه‌نگار/SMS.ir/آریانت) نوشته شود. تا آن زمان
   شماره فقط ذخیره می‌شود.
3. **چند کاربره (کارتابل):** تعریف کاربران، متولی هر جلسه/کار، نمایش کارتابل و
   تقویم هر نفر و نمای مدیر. این روی همان مدل دادهٔ سینک سوار می‌شود ولی نیاز
   به جدول‌های «مالکیت» و مجوزها دارد.
4. **نسخهٔ شبکهٔ داخلی:** اجرای یک سرور در شبکهٔ محلی (بدون اینترنت) و دسترسی
   از دستگاه‌های دیگر؛ نیازمند یک لایهٔ API/احراز هویت روی همان دیتابیس است.
5. **تکمیل موبایل:** ویجت‌های اندروید برای ماژول‌های سبک (به‌جای بک‌گراند
   دسکتاپ)، و هر ماژولی که بعداً اضافه شد باید در `MobileShell` هم دیده شود.
6. **مسیر ERP (اختیاری و بلندمدت):** افزودن ماژول‌های سازمانی روی همین
   معماری؛ تصمیم فعلی این است که ابتدا نسخهٔ شخصی پایدار شود.

## ۴) تصمیم‌های ثبت‌شده (نقض نکنید)

- **آفلاین‌محور:** SQLite منبع حقیقت است؛ حساب و سینک اختیاری‌اند و برنامه
  بدون اینترنت کامل کار می‌کند.
- **بدون سرور اجباری:** هیچ قابلیت اصلی نباید به شبکه وابسته شود.
- **دادهٔ کاربر قابل خروجی:** هر ماژول باید خروجی/بکاپ داشته باشد؛ حذف در
  ماژول‌های کاری به «بایگانی» تبدیل می‌شود، نه پاک‌شدن.
- **امضای ثابت اندروید:** همهٔ APKها با `resa-release.jks` امضا می‌شوند.
- **نسخهٔ همیشه صعودی** و notes انتشار به انگلیسی.
- **فارسی و RTL پیش‌فرض** در دسکتاپ و موبایل.
- **ظاهر:** مرجع `design.md` است؛ گرافیک گیاهان با SVG اختصاصی و کهنه‌شدن
  تدریجی رنگ (نه خراب‌شدن شکل) ساخته شده — [جزئیات](resa-plants.fa.md).

## ۵) ریسک‌ها و نکات نگهداری

- `D:\RESA desktop\android-signing\resa-release.jks` و رمزش را نگه دارید؛ بدون
  آن انتشار آپدیت اندروید ممکن نیست.
- پوشهٔ `src-tauri/gen/android/app/generated/` و `tauri.properties` تولیدی‌اند
  و در git نیستند؛ روی ماشین تازه با `scripts/android-gen-gradle.mjs` ساخته
  می‌شوند.
- فایل‌های `oauth-credentials.json` و `.env` هرگز کامیت نشوند.
- قبل از هر انتشار، `npm run version:check` و CI سبز را ببینید.
- گزارش باگ‌ها و درخواست‌ها از مسیر `resa.config.json` (repo و ایمیل) خوانده
  می‌شود؛ اگر ریپو عوض شد، همان فایل را به‌روز کنید.

## ۶) چک‌لیست شروع دوبارهٔ کار

```powershell
cd "D:\RESA desktop\nowly-src"
git pull
npm ci
npm run version:check
npm test
npm run tauri dev
```

اگر می‌خواهید نسخهٔ جدید منتشر شود: تغییرات را روی `mobile` کامیت و push
کنید، CI سبز را ببینید، بعد `git push origin mobile:main` تا `release.yml`
نسخهٔ بعدی را بسازد و APK و نصاب‌ها را کنار هم منتشر کند.
